# Техническое задание на разработку генератора QR-кодов для ссылок и текста

## 1. Наименование и область применения

**Наименование программы:** «Генератор QR-кодов для ссылок и текста».

**Область применения:** веб-приложение для подготовки QR-кодов, которые можно разместить в презентации, документе или на печатном материале. Пользователь вводит ссылку или произвольный текст, проверяет результат на экране и сохраняет изображение. Регистрация и серверное хранение данных не требуются.

**Результат работы:** QR-код, из которого после считывания восстанавливается ровно введённая строка. Для ссылки это адрес, который откроется после подтверждения в приложении-сканере; для текста — исходный текст, включая регистр, знаки препинания и пробелы внутри строки.

## 2. Функциональные требования

### 2.1. Ввод ссылки

- **FR-01.** Программа должна предоставлять режим «Ссылка» с подписанным полем ввода. [Задача #1](https://github.com/Zefeld/qr-code-generator-srs/issues/1).
- **FR-02.** В режиме «Ссылка» программа должна принимать непустой адрес с протоколом `http://` или `https://` и именем хоста. Адрес с пробелами или управляющими символами, с другим протоколом либо длиннее 1000 байт в UTF-8 должен отклоняться с объяснением причины. Ведущие и замыкающие пробелы не должны удаляться незаметно. [Задача #1](https://github.com/Zefeld/qr-code-generator-srs/issues/1).

### 2.2. Ввод текста

- **FR-03.** Программа должна предоставлять режим «Текст» с многострочным подписанным полем ввода. Ввод Unicode, включая кириллицу и переносы строк, должен поддерживаться. [Задача #2](https://github.com/Zefeld/qr-code-generator-srs/issues/2).
- **FR-04.** Программа должна отклонять пустой текст, строку из одних пробельных символов и текст длиннее 1000 байт в UTF-8. Допустимый текст должен передаваться в QR-код без удаления значимых пробелов, переносов строк и знаков. [Задача #2](https://github.com/Zefeld/qr-code-generator-srs/issues/2).

### 2.3. Генерация и просмотр QR-кода

- **FR-05.** После нажатия кнопки «Создать QR-код» программа должна строить QR-код для строки из активного режима и показывать его на странице. Генерация должна выполняться только после успешной проверки ввода. [Задача #3](https://github.com/Zefeld/qr-code-generator-srs/issues/3).
- **FR-06.** QR-код должен использовать коррекцию ошибок уровня M, чёрные модули на белом фоне и свободное поле вокруг кода шириной не менее четырёх модулей. Считанная строка должна совпадать с введённой посимвольно. [Задача #3](https://github.com/Zefeld/qr-code-generator-srs/issues/3).
- **FR-07.** После изменения входных данных ранее созданный код должен скрываться, а сохранение — блокироваться до повторной генерации. [Задача #3](https://github.com/Zefeld/qr-code-generator-srs/issues/3).

### 2.4. Сохранение изображения

- **FR-08.** Программа должна предоставлять кнопку «Скачать PNG» только после успешной генерации. Файл должен иметь размер 512 × 512 пикселей, включать весь QR-код вместе со свободным полем и иметь имя `qr-link.png` или `qr-text.png` в зависимости от режима. [Задача #4](https://github.com/Zefeld/qr-code-generator-srs/issues/4).
- **FR-09.** Сохранённый PNG должен считываться как та же строка, что показана в предварительном просмотре. [Задача #4](https://github.com/Zefeld/qr-code-generator-srs/issues/4).

### 2.5. Сценарий использования

1. Пользователь выбирает «Ссылка» или «Текст» и вводит данные.
2. Пользователь нажимает «Создать QR-код».
3. Программа проверяет ввод. При ошибке она показывает причину и предлагает исправить данные; изображение не создаётся.
4. При корректном вводе программа показывает QR-код.
5. Пользователь нажимает «Скачать PNG» и получает изображение.

## 3. Требования к надёжности и обработке ошибок

- **REL-01.** При ошибке проверки ввода или генерации программа должна показывать понятное сообщение, не предлагать скачать устаревший QR-код и сохранять введённые данные для исправления. [Задача #6](https://github.com/Zefeld/qr-code-generator-srs/issues/6).
- **REL-02.** Генерация и сохранение должны выполняться в браузере без передачи введённой строки на внешний сервер. Это проверяется по сетевым запросам во время выполнения операций. [Задача #6](https://github.com/Zefeld/qr-code-generator-srs/issues/6).
- **REL-03.** Для строки длиной до 1000 байт в UTF-8 время от нажатия «Создать QR-код» до появления изображения должно составлять не более одной секунды минимум в 19 из 20 последовательных запусков на устройстве с 2 ГБ ОЗУ в поддерживаемом браузере. [Задача #6](https://github.com/Zefeld/qr-code-generator-srs/issues/6).

## 4. Требования к интерфейсу

- **UI-01.** Все надписи, подсказки и сообщения об ошибках должны быть на русском языке. Активный режим, поле ввода и основное действие должны быть различимы без инструктажа. [Задача #5](https://github.com/Zefeld/qr-code-generator-srs/issues/5).
- **UI-02.** Интерфейс должен работать при ширине окна от 320 пикселей без горизонтальной прокрутки. Предварительный просмотр должен целиком помещаться по ширине окна. [Задача #5](https://github.com/Zefeld/qr-code-generator-srs/issues/5).
- **UI-03.** Переключение режима, ввод, генерация и сохранение должны быть доступны с клавиатуры. Поля должны иметь видимые подписи, ошибки должны быть связаны с соответствующими полями, а результат генерации должен объявляться вспомогательным технологиям. [Задача #5](https://github.com/Zefeld/qr-code-generator-srs/issues/5).

## 5. Требования к техническому обеспечению

- **TECH-01.** Приложение должно запускаться в браузере без установки отдельной программы и без учётной записи. [Задача #5](https://github.com/Zefeld/qr-code-generator-srs/issues/5).
- **TECH-02.** Поддерживаемые среды при приёмке: Windows 10/11 и macOS 12+ с Chrome 120+, Firefox 120+, Edge 120+ или Safari 17+; Android 10+ с Chrome 120+; iOS 17+ с Safari 17+. Минимальный объём ОЗУ устройства — 2 ГБ. [Задача #5](https://github.com/Zefeld/qr-code-generator-srs/issues/5).
- **TECH-03.** Приложение должно состоять из статических файлов, которые можно разместить на обычном веб-сервере с HTTPS; для генерации QR-кода серверная обработка не требуется. [Задача #6](https://github.com/Zefeld/qr-code-generator-srs/issues/6).

## 6. Проверка выполнения требований

Для приёмки следует проверить корректную ссылку, ссылку с неподдерживаемым протоколом, пустой ввод, текст с кириллицей и переносом строки, ровно 1000 байт UTF-8 и 1001 байт UTF-8. Полученные изображения нужно считать независимым QR-сканером и сравнить результат с исходной строкой. Проверки интерфейса провести на ширине 320 пикселей и с управлением только с клавиатуры. Критерии по каждому требованию приведены в связанных Issues.
